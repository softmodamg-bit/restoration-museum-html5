# 관장 랭킹 배포 안내

## 현재 구현 상태

기록실의 **현재 기록 제출** 버튼은 파일을 내려받게 하지 않습니다. 클릭한 시점의 세이브에서 랭킹에 필요한 복원 성과만 메모리에서 만들고 Google Apps Script 웹 앱으로 즉시 전송합니다.

Apps Script 주소를 연결하기 전에는 **심사용 데모 모드**로 동작합니다. 이때도 실제 제출과 같은 데이터 추출과 점수 계산 결과를 게임 안에서 확인할 수 있지만 외부 데이터는 전송하지 않습니다.

관련 파일은 다음과 같습니다.

- `js/ranking-config.js`: 배포 주소와 시즌 설정
- `js/game.js`: 제출 자료 생성, 원클릭 전송, 데모 화면
- `ranking-apps-script.gs`: 검증, 서버 점수 재계산, Google Sheets 저장, 랭킹·제출 결과 페이지

## Google Apps Script 연결

1. Google Drive에서 빈 Google Sheet를 만듭니다.
2. 시트 상단의 **확장 프로그램 → Apps Script**를 엽니다.
3. 기본 `Code.gs` 내용을 모두 지우고 프로젝트의 `ranking-apps-script.gs` 전체를 붙여 넣습니다.
4. 함수 목록에서 `setupRankingSheet`를 선택해 한 번 실행하고 권한을 승인합니다.
5. **배포 → 새 배포 → 유형: 웹 앱**을 선택합니다.
6. **다음 사용자로 실행: 나**, **액세스 권한: 모든 사용자**로 배포합니다.
7. 배포 결과의 `/exec`로 끝나는 URL을 복사합니다. `/dev` 테스트 URL은 사용하지 않습니다.
8. `js/ranking-config.js`의 `endpoint`에 URL을 넣습니다.

```js
window.RESTORATION_RANKING_CONFIG = Object.freeze({
  endpoint: "https://script.google.com/macros/s/배포_ID/exec",
  season: "공모전 시즌 1",
  gameVersion: "prototype-2026-08",
  rulesVersion: "director-score-v3"
});
```

게임을 새로 열어 기록실 배지가 **공용 랭킹 연결됨**으로 바뀌면 연결된 것입니다.

## 제출되는 정보

공개 랭킹에는 다음 정보만 표시됩니다.

- 관장 이름
- 미술관 이름
- 복원 작품 수
- 평균 정확도
- 평균 위험도
- 누적 개관 수입
- 누적 관람객
- 전체 이야기 완주일
- 관장 점수

서버 검증에는 작품 ID, 복원 날짜, 정확도, 최종 위험도, 작업 시간과 누적 개관 수입·누적 관람객·이야기 진행도·완주일이 함께 전달됩니다. 전체 세이브, 현재 보유 코인, 음량과 글자 크기 같은 개인 설정은 보내지 않습니다. 익명 플레이어 ID는 Apps Script의 비공개 salt와 함께 SHA-256으로 해시한 값만 시트에 저장합니다.

## 점수와 조작 방지

관장 점수는 작품별로 다음 식을 적용해 서버에서 다시 계산합니다.

```text
작품 점수 = 정확도 × 100 + 시간 가산점 - 위험도 × 10 + 복원 다양성 250
수입 보너스 = min(5,000, 누적 개관 수입 ÷ 25의 버림)
관람객 보너스 = min(5,000, 누적 관람객 ÷ 5의 버림)
이야기 보너스 = 후일담 5편까지 완주한 날짜에 따라 1,500~5,000
관장 점수 = 제출된 서로 다른 작품의 작품 점수 합계 + 수입·관람객·이야기 보너스
```

- 정확도 80% 미만 또는 작업 시간이 없는 옛 기록은 시간 가산점이 없습니다.
- 165초 이내는 300점, 240초 이내는 200점, 300초 이내는 100점입니다.
- 작품 ID 중복, 날짜 역전, 범위를 벗어난 정확도·위험도·시간은 거부합니다.
- 5초 미만의 작업 기록은 자동 공개하지 않고 시트에서 `검토 필요`로 분류합니다.
- 후일담 5편까지 20일 이내 완주하면 5,000점, 25일 이내 4,500점, 35일 이내 3,500점, 50일 이내 2,500점, 이후에는 1,500점입니다. 미완주는 0점입니다.
- 누적 수입과 관람객 보너스는 각각 최대 5,000점으로 제한해 복원 점수를 지나치게 압도하지 않게 합니다.
- 동일 시즌의 같은 플레이어는 최고 기록 하나만 유지합니다.
- 동점이면 평균 정확도, 낮은 위험도, 짧은 총 작업 시간 순으로 정렬합니다.
- 관장명과 미술관명은 서버에서도 길이, 문자, 반복 글자, 욕설, 연락처를 다시 검사합니다.

정적 HTML 게임이므로 의도적인 기록 조작을 완전히 차단할 수는 없습니다. 이 구현은 간단한 세이브 편집을 막고 공모전·지인 테스트 규모에서 의심 기록을 분리하는 수준입니다. 상금이나 중요한 경쟁으로 확장한다면 작품 복원 완료 시 서버가 서명한 체크포인트를 추가해야 합니다.

## 운영할 때 확인할 것

- 밸런스가 바뀌면 `season` 또는 `rulesVersion`을 바꾸고 Apps Script의 같은 상수도 맞춥니다.
- Apps Script를 수정한 뒤에는 기존 배포를 **새 버전으로 다시 배포**해야 반영됩니다.
- `director-score-v3`는 기존 행과 같은 시트에 보존되지만 공개 랭킹과 최고 기록 비교에는 v3 행만 사용합니다.
- 시트에서 `검토 필요` 기록을 확인한 뒤 정상 기록이면 `status` 셀을 `정상`으로 바꿀 수 있습니다.
- 공개 배포 전에 실제 배포 URL로 제출, 최고 기록 갱신, 모바일 새 창 열기를 한 번씩 시험합니다.
