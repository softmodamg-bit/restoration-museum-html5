# Codex 작업 브리프

## 프로젝트 목표

HTML5 공모전 제출용으로, ‘미술품 복원’의 전후 만족감과 ‘미술관 운영’의 성장감을 10분 안에 보여 주는 플레이 가능한 게임을 완성한다.

## 절대 유지 조건

- 외부 서버 없이 정적 호스팅 가능
- 모바일 터치와 데스크톱 마우스 모두 지원
- 화면 폭 360px 이상 대응
- localStorage 저장 호환 유지
- 기존 4개 작품의 복원·전시·기록 흐름 유지
- 불필요한 프레임워크 추가 금지. 도입 시 이유와 빌드 결과를 문서화
- 위험한 화학 배합이나 실제 전문 처리를 따라 하게 만드는 표현 금지
- 복원은 ‘새것 만들기’가 아니라 조사·안정화·최소 개입·기록이라는 방향 유지

## 0단계 — 먼저 할 일

1. 전체 파일을 읽고 현재 구조를 요약한다.
2. 로컬 서버를 실행한다.
3. 데스크톱과 390px 모바일 뷰에서 다음 흐름을 직접 테스트한다.
   - 새 게임
   - 달항아리 복원
   - 결과 보상
   - 전시관 배치
   - 다음 날 개관
   - 새로고침 후 저장 복구
4. 콘솔 오류와 레이아웃 문제를 목록화한다.
5. 수정 전 작업 계획과 영향을 받는 파일을 제시한다.

## 1단계 — 공모전용 버티컬 슬라이스 강화

### 목표
첫 작품의 체험을 고유 미니게임으로 바꾼다.

### 구현
- 도자기 파편 3개를 드래그해 윤곽에 맞추는 단계
- 잘못 놓으면 제자리로 돌아오며 위험도 소폭 상승
- 성공 시 접합선이 차례로 안정화되는 애니메이션
- 마지막 보색 단계 전/후 비교 슬라이더
- 첫 플레이에만 등장하는 4단계 튜토리얼 오버레이

### 완료 조건
- 마우스와 터치로 파편 드래그 가능
- 화면 회전·리사이즈 후에도 좌표가 맞음
- 키보드만으로도 건너뛰기 가능
- 새로고침 시 작품 복원 완료 상태 유지

## 2단계 — 작품별 고유성

- 종이: 찢김을 따라 보존용 종이 조각 배치
- 유화: 3개 시험구 중 변색만 줄고 안료는 유지되는 시험구 선택
- 금속: 활성 부식과 안정한 녹을 구분해 제거 범위 선택
- 공통 드래그 타깃 방식은 fallback으로 남긴다.

## 3단계 — 운영 게임 강화

- 작품 조합에 따른 전시 테마 보너스
- 관람객 유형 4종과 간단한 선호
- 교육 프로그램 2종, 특별전 1종
- 하루 운영 결과에 방문객 구성과 만족도 표시
- 시설 업그레이드의 시각적 변화 반영

## 4단계 — 폴리시

- 버튼·카드 hover/tap 애니메이션 정리
- 실제 OGG 효과음으로 교체하되 라이선스 파일 포함
- 첫 화면 로딩 최적화
- 이미지가 추가되면 WebP 및 2x 리소스 사용
- 접근성: 색만으로 상태를 구분하지 않기, aria-label, 키보드 흐름 확인
- `prefers-reduced-motion` 유지

## 5단계 — 빌드/QA

- Chrome, Edge, Safari 모바일 기준 핵심 플로우 점검
- 360×800, 390×844, 768×1024, 1366×768, 1920×1080 확인
- 네트워크 오프라인 상태에서 시작 화면과 저장 기능 확인
- Lighthouse 성능·접근성·Best Practices 결과 기록
- `docs/QA_REPORT.md` 생성
